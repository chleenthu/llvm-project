# Affine Vector-Index Optimization

`ExpandPseudos::ProcessInSameAffine` is enabled by the hidden `--custom-a` option.  It
recognizes a vector index generated by `PseudoVID_V_M8` and folds a scalar base
addition expressed as `PseudoVOR_VX_M8` into vector addition.

Let `i` be the lane number produced by `VID`.  The target is
the common affine form:

```text
index_0[i]  = block_start + i
index_k[i]  = block_start + i + k       (k = 32, 64, 96)
mask_k[i]   = index_k[i] < n_elements
```

All instructions below must be in the same machine basic block.

## Intended pattern

Before rewriting, there are one base vector and three offset vectors:

```text
%10 = PseudoVID_V_M8 ..., %9                 # i = 0..31
%11 = disjoint PseudoVOR_VX_M8 ..., %10, %8  # block_start + i

%13 = PseudoVADD_VX_M8 ..., %10, %12         # i + 96
%14 = disjoint PseudoVOR_VX_M8 ..., %13, %8
%21 = PseudoVMSLT_VX_M8 %14, %3, %9

%16 = PseudoVADD_VX_M8 ..., %10, %15         # i + 64
%17 = disjoint PseudoVOR_VX_M8 ..., %16, %8

%18 = PseudoVADD_VX_M8 ..., %10, %9          # i + 32
%19 = disjoint PseudoVOR_VX_M8 ..., %18, %8
```

The rewritten block shows the canonical form for all three offsets:

```text
%14 = PseudoVADD_VX_M8 ..., %11, %12          # block_start + i + 96
%17 = PseudoVADD_VX_M8 ..., %11, %15          # block_start + i + 64
%19 = PseudoVADD_VX_M8 ..., %11, %9           # block_start + i + 32
```

That is, it changes the representation from `(i + k) OR base` to
`(i OR base) + k`.

## Example

Before rewriting, the pattern has 3 VADD, 4 VOR:

```text
[0...31]
[block_start + 0, ..., block_start + 31]
[32...63]
[block_start + 32, ..., block_start + 63]
[64...95]
[block_start + 64, ..., block_start + 95]
[96...127]
[block_start + 96, ..., block_start + 127]
```

The rewritten block has only 3 VADD, 1 VOR:

```text
[0...31]
[block_start + 0, ..., block_start + 31]
[block_start + 32, ..., block_start + 63]
[block_start + 64, ..., block_start + 95]
[block_start + 96, ..., block_start + 127]
```

## What `ProcessInSameAffine` actually checks

- It starts at `PseudoVID_V_M8`.
- It records the last use of the VID result that is a `PseudoVOR_VX_M8` whose
  third operand is that VID result; this supplies `base_index` and `base`.
- Every other VID user is a candidate when its operand 3 is a virtual register
  uniquely defined by `ADDI`.
- It selects the first `PseudoVOR_VX_M8` use of `tmp`, without checking that
  this `VOR` uses `tmp` or the same `base`.
- It creates a `PseudoVADD_VX_M8` at the selected `VOR`, using the original
  base-index vector, the candidate's scalar operand, and the VID's `vl`.
- It redirects the first `PseudoVMSLT_VX_M8` whose operand 1 is the old `VOR`
  result, then erases the old `VOR` and candidate instruction.
